2 End-to-End Enlistment & Commissioning Workflow

This pipeline transitions a volunteer from initial digital application to a fully commissioned, uniformed Sainik with a unique alphanumeric ID and cryptographic QR credentials.

1
Candidate Enlistment Submission Public Web
Volunteer accesses membership.html and completes a 5-step form: Personal Bio, Educational & Professional Background, Residential Jurisdiction (State → District → Taluka → Chapter), Wing Allocation (Cadet Corps, Mahila Dal, Youth Wing, etc.), Photo/ID Document Upload, and acceptance of the Solemn Pledge.
2
Automated Indexing & Tracking ID Generation Server Engine
Backend generates a cryptographically random, collision-resistant Application Tracking ID (SSD-2026-XXXXXX). The record is stored with status SUBMITTED and assigned to the local district queue.
3
District Officer Verification & Assessment Rubric Territorial Command
The assigned District Commander or Enlistment Officer accesses admin.html. Enforced by territorial RBAC, they only see candidates in their district. The officer performs background checks and completes the 4-point assessment rubric:
  • Identity Verification: Photo and Government ID authenticity.
  • Background & Integrity: Community standing and moral character.
  • Physical Readiness: Suitability for drill, parade, and field mobilization.
  • Wing Alignment: Aptitude for specific specialized directorates.
The record status advances to RECOMMENDED with signed officer remarks.
4
Central Command Final Approval & Commissioning Central Directorate
The National President, Central Admin, or Commissioning Board conducts the final review. Upon approval:
  • System commissions an official Sainik ID: SSD-[STATE]-2026-[NUMBER] (e.g. SSD-MH-2026-001245).
  • Generates a secure, tamper-proof QR verification token (qr_tok_...).
  • Inserts the record into the permanent members active cadre registry.
  • Transitions application status to FINAL_APPROVED.
5
Digital ID Card & Member Portal Activation Cadre Service
The newly commissioned Sainik can log into member-portal.html to view their official Digital ID card, download print-ready credentials, view active unit assignments, and access national circulars.

3 Public QR Verification & Anti-Fraud Shield

Designed for rapid verification by civil authorities, police, event organizers, and the public during rallies and disaster response operations.

5-Tier High-Availability Lookup Pipeline
When a QR code is scanned or an identifier is submitted on verify.html:
  1. URL Normalization: Strips host and query parameters if a native mobile camera app returns the full browser link.
  2. Tier 1 — Backend API: Queries GET /api/verify/:id.
  3. Tier 2 — Card API Fallback: Calls GET /api/members/card/:id if primary endpoint is busy.
  4. Tier 3 — Direct Supabase Client: Direct browser-to-database query via Supabase JS SDK.
  5. Tier 4 — Local Storage Cache: Reads cached offline credential records.
  6. Tier 5 — Algorithmic Validation: Validates checksum patterns for emergency validation.
Supported Identification Tokens
The verification engine accepts any of the following parameters:
  • Official Sainik ID: SSD-MH-2026-001245
  • Application Reference: SSD-2026-8F42K7
  • 10-Digit Mobile Number: 9822341927
  • Cryptographic QR Token: qr_tok_...

4 Treasury, Razorpay & 80G Tax Exemption Workflow

Processes voluntary public contributions with automated tax exemption receipts under Section 80G of the Indian Income Tax Act.

1
Donor Order Initiation Public Client → Server API
Donor specifies amount, cause (General Welfare, Relief Fund, Training Academy), PAN number, and contact details. Server calls razorpay.orders.create() to register an immutable transaction order.
2
Razorpay Universal Checkout Secure Payment Gateway
Browser launches Razorpay's standard checkout dialog supporting UPI (Google Pay, PhonePe, Paytm), Credit/Debit Cards, NetBanking, and Wallets.
3
Cryptographic Signature Verification Server Security
Payment response is sent to POST /api/donations/verify. The backend generates an HMAC-SHA256 digest using the secret key and ensures the signature matches before registering the donation as completed.
4
Automated 80G Receipt Issuance Treasury Ledger
System generates an official sequential receipt number (SSD-REC-2026-XXXXXX). The donor instantly views and downloads a signed, printable donation certificate featuring SSD registration numbers and 80G tax exemption clauses.

5 Role-Based Access Control (RBAC) & Territorial Scope

The platform enforces granular administrative separation between strategic central command and field operations.

Role Identifier Administrative Scope Permissions & Capabilities
super_admin National Unlimited Full platform control: System settings, user role provisioning, database migrations, audit trail access, and final approval override.
central_admin National Command Central Executive authority: Commissioning recommended candidates, appointing state leadership, and publishing official gazettes.
finance_admin National Treasury Financial ledger management: Reconciliation of Razorpay collections, 80G tax receipt audits, and expenditure reporting.
state_official Single State Boundary State Directorate: Oversees district units within their assigned state (e.g. Maharashtra), manages state events, and reviews escalations.
district_official Single District Boundary District Command: Inspects candidate documents, conducts assessment rubric reviews, and forwards applications with recommendation flags.
enlistment_officer Enlistment Queue Only Focused verification officer: Reviews pending submissions and verifies applicant ID credentials. Restricted from treasury and system admin.
